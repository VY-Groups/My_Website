# VY-Groups Migration Guide

> **Goal:** turn this site (currently Yash Kumar Dubey's personal portfolio)
> into the **official web presence of VY-Groups** — with as little friction as
> possible, because identity is no longer hardcoded anywhere.
>
> Prepared: 2026-10-02 · All identity strings live in **`site.config.js`**.

---

## 0. How the identity system works

```
site.config.js  (single source of truth — edit this ONE file)
      │
      ├── src/config/site.js ──► React app (Hero, Nav, Footer, Contact,
      │                          Collaboration, Projects, SuccessStories,
      │                          StudentResources, SEO/JSON-LD)
      │
      ├── scripts/apply-identity.js ──► index.html (markers), manifest.webmanifest, sw.js precache
      │
      ├── scripts/generate-seo.js ──► sitemap.xml + robots.txt (every build)
      │
      ├── api/templates.js, api/send-email-handler.js ──► email branding
      │
      └── scripts/check-identity.js ──► audit for leftover strings
```

Commands (also in `package.json`):

| Command | Purpose |
|---|---|
| `npm run identity` | Write `site.config.js` values into index.html / manifest / sw.js |
| `npm run identity:check` | Verify those files are in sync (CI-friendly, exit 1 on drift) |
| `npm run identity:audit` | Scan the repo for identity strings, classify every hit |
| `node scripts/check-identity.js "Old Name" old@example.com` | After migration: hunt **legacy** values |

## 1. Edit `site.config.js`

| Field | Current (personal) | Set to (company example) |
|---|---|---|
| `site.name` | `Yash Kumar Dubey Portfolio` | `VY-Groups` |
| `site.shortName` | `Yash Kumar Dubey` | `VY-Groups` |
| `site.title` | `Yash Kumar Dubey - DevOps…` | `VY-Groups - Software, Cloud & Automation` |
| `site.url` | `https://yashkumardubey.dev` | `https://vygroups.co.in` (or the new domain) |
| `site.repo` | personal repo URL | company repo URL |
| `site.description` / `shortDescription` / `manifestDescription` | personal SEO copy | company boilerplate |
| `site.keywords` | personal keywords | company keywords |
| `site.ogImageAlt` | `Yash Kumar Dubey - DevOps Engineer` | `VY-Groups logo` |
| `owner.*` | Yash's details | **Keep or replace** — on a company page you may keep the founder's contact, or switch to `info@vygroups…`, company address, etc. |
| `socials.*` | personal GitHub/LinkedIn | company accounts (or keep founder's + add org handles) |
| `org.*` | VY-Groups | unchanged ✓ (already the company) |
| `colors.*` | blue brand | rebrand colors if desired (also updates `theme-color` meta + manifest) |

> `org` already describes VY-Groups — on the company page this likely becomes
> the *primary* identity, while `owner` shrinks to a "Founder" sub-section.

## 2. Regenerate the static files

```bash
npm run identity          # index.html + manifest.webmanifest + sw.js
npm run build             # sitemap.xml + robots.txt regenerate automatically
npm run identity:check    # must pass
```

What each tool owns:

| File | Mechanism |
|---|---|
| `index.html` | regions between `<!-- identity:*:start/end -->` markers (preload photo, meta/OG/Twitter block, Person+Organization JSON-LD) |
| `public/manifest.webmanifest` | fully generated from config |
| `public/sw.js` | precache list between `// identity:precachelist:start/end` |
| `public/sitemap.xml`, `public/robots.txt` | regenerated by `scripts/generate-seo.js` on every build |

**Manual bump:** `sw.js` → set `CACHE_VERSION = 'portfolio-v2'` (or `vygroups-v1`)
so returning PWA users fetch the new assets.

## 3. Swap the assets

| Asset | Current | Company |
|---|---|---|
| `public/pic.jpeg` | Yash's photo (400×400, used by `<link rel=preload>` + Hero + OG image) | company logo/hero image — **keep the filename or update `owner.photo`** |
| `public/favicon.png`, `public/apple-touch-icon.png` | personal mark | company mark |
| `public/Yash_Kumar_Dubey_Resume.pdf` | resume | delete (and remove from `owner.resume` + nav download behavior) |
| OG image dimensions | 400×400 declared | update `og:image:width/height` in the `meta` region generator if the new logo differs |

Run `npm run optimize` (sharp) if the new images are heavy.

## 4. Restructure the content

Section-by-section for a company page:

| Section | Action |
|---|---|
| Hero | Company headline ("We build scalable software, cloud & automation") — name/role already come from config |
| Experience | **Personal** — replace with company timeline (founding, milestones) or remove |
| Skills | **Personal** — replace with capabilities/services grid |
| Projects | Keep (already lists VY-Groups repos), reframe as "Products" |
| Success Stories | **Already the VY-Groups showcase** ✓ — promote it higher up the page |
| Blog | Keep or drop |
| Student Resources | Personal/education — likely remove for a company page |
| Collaboration | Rewrite as "Work with us" / services inquiry |
| Contact | Company mailbox + address (update `owner.email` / `owner.location`) |
| Footer | `org` links already present ✓ |

Analytics events (`trackEvent`) and tests follow config automatically.

## 5. Environment & Vercel

| Key | Where | Action |
|---|---|---|
| `VITE_SITE_URL` | Vercel + `.env.example` | new canonical URL |
| `GMAIL_USER` / `GMAIL_APP_PASSWORD` | Vercel | company mailbox (auto-reply subject follows config ✓) |
| `HCAPTCHA_SITE_KEY` / `HCAPTCHA_SECRET_KEY` | Vercel | add the **new domain** to hCaptcha's allowed hosts |
| Analytics key | Vercel | company analytics property |
| Slack/Discord webhooks | Vercel | update if desired |

## 6. Domain & SEO

1. Point the domain DNS at Vercel (project *my-website* or a new project).
2. `site.url` change flows to: canonical, OG/Twitter URL, sitemap, robots, JSON-LD, email footers — all automatic.
3. Optional: 301-redirect `yashkumardubey.dev` → new domain (Vercel redirects config).
4. Re-submit sitemap in Google Search Console for the new domain; re-verify properties.
5. Validate: `node scripts/check-jsonld.js`, Share Debuggers (meta previews), `npm run build`.

## 7. Verify

```bash
npx vitest run                 # tests assert against config, not literals
npm run build                  # SEO files regenerate
node scripts/check-jsonld.js
npm run identity:check
node scripts/check-identity.js "Yash Kumar Dubey" "ydubey020@gmail.com" "yashkumardubey.dev" "Yash_Kumar_Dubey_Resume.pdf"
```

The final audit must show **✓ PASS — no unexpected identity references**.
Expected `[docs]` hits (LICENSE, README, historical markdown) are intentional.

**Manual smoke test:** navbar brand, footer, contact mailto, collaboration
quick links, resume button (removed?), PWA install prompt, form emails arrive
at the new mailbox.

## 8. Rollback

Everything is one commit-range away: `git revert` the migration commits, or
revert `site.config.js` and re-run `npm run identity && npm run build`.
